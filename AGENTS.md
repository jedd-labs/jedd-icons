# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, Codex, Cursor, etc.) when working with code in this repository.

## What this is

A pnpm + Turbo monorepo that builds and distributes a set of SVG icons as published npm packages. Source SVGs are the source of truth; a codegen tool turns them into per-icon TypeScript files that are then bundled by tsdown. The published surface is `@jedd-icons/react` (React components) and `@jedd-icons/core` (framework-agnostic icon nodes).

## Commands

- `pnpm icons:compare [--ref <git-ref>] | --from <dir> [--variant stroke]` — checks re-exported icons against the committed ones (every icon SVG changed since the ref, default `HEAD`, or every SVG in an export folder). Verdicts: `identical` (same bytes shipped), `same geometry` (reordered/reversed/`<circle>` vs path), `restructured` (same segments, split into strokes differently), `CHANGED` (lists moved segments and by how much). It also lists `ANIMATED` icons whose elements moved to another position, even with the same shape: their animation files target elements by position. Use it when re-exporting icons.
- `pnpm icons` — full pipeline: normalize source SVGs (`icons:clean`), check them (`icons:check`), then build every package via Turbo. **Run this after adding/changing any icon.**
- `pnpm icons:check` — read-only check of the source SVGs, their `.json` metadata (normalized, no export problems, 1px margin, valid against `icon.schema.json`) and their animation files (fit the icon's geometry); exits 1 on errors, warnings for what may be intended.
- `pnpm build` — build all packages (Turbo, respects `^build` dependency order).
- `pnpm dev` — Turbo dev across the workspace.
- `pnpm --filter www-docs dev` — run just the gallery/docs site (`http://localhost:3000`).
- `pnpm --filter @jedd-icons/react gen` — regenerate icon `.ts` files only (no bundle).
- `pnpm --filter @jedd-icons/react dev` — gen + tsdown `--watch` for the React package.
- `pnpm --filter @jedd-icons/react-animated gen` — regenerate the animated icons (refuses an animation file `icons:check` would reject).
- `pnpm lint` / `pnpm check` — `ultracite check` (Biome). `pnpm format` / `pnpm fix` — `ultracite fix`.
- `pnpm typecheck` — `turbo typecheck` (per-package `tsc --noEmit`).
- `pnpm knip` — find unused files, exports, and dependencies (config in `knip.json`). Needs the generated sources, so run `pnpm build` or `pnpm typecheck` first on a fresh checkout. **Run after removing code or deps.**
- `pnpm test` — `turbo test`: vitest suites in `tools/build-icons` (cleaning, check rules, codegen, animated codegen, geometry) and `packages/shared`.

The quality gate is `icons:check` + lint + test + typecheck + knip. Locally it's enforced by Lefthook git hooks (pre-commit lints staged files; pre-push runs `turbo typecheck` then `knip`, alongside `ultracite check`). CI (`.github/workflows/ci.yml`) runs on every PR and push to `main` as two jobs, both required status checks on `main`: `Icons` runs `pnpm icons:check` (no build needed; issues show as annotations on the PR's files), and `Lint, typecheck & build` runs lint → test → build → knip → typecheck (knip needs the generated sources, so it runs after the build; findings show as PR annotations). Bypass the local hooks with `git commit --no-verify` or `LEFTHOOK=0 git push`.

Node >= 20, pnpm 11.5.1. Dependency versions are pinned centrally in `pnpm-workspace.yaml` under `catalog:` — packages reference `"catalog:"` instead of literal versions, so add/bump deps there.

## Architecture: the icon build pipeline

The whole system exists to turn `icons/**/*.svg` into typed, tree-shakeable component modules. The chain is worth understanding before touching anything under `packages/`, because most of `packages/{react,core,react-animated}/src` is **generated and gitignored/lint-ignored** (see `biome.jsonc` `files.includes` exclusions for `src/icons`, `src/icons-*`).

1. **`icons/<variant>/<name>.svg` + `<name>.json`** — source of truth. Note the layout is `icons/stroke/` (a variant subdirectory), **not** flat `icons/<name>.svg` as the README's "Adding icons" section implies. Each variant directory is discovered dynamically; `stroke` is the `DEFAULT_VARIANT` and today the only one. There's no fill variant (it was removed); a future rounded set would be another stroked variant in `icons/rounded/`, exported under a `/rounded` subpath, possibly covering only some icons. Adding one means a `Variant` member and defaults in `@jedd-icons/shared`, an entry in `VARIANT_ROOT_ATTRS`, the package `exports` (`react-animated` too), and gitignore/biome/knip entries for the generated `src/<variant>.ts`. `<name>.json` metadata is validated against `icon.schema.json` (required: `contributors`, `tags`, `categories` where `categories` is a closed enum).

2. **`tools/build-icons/clean-icons.ts`** — normalizes source SVGs in place: sets canonical root attributes and strips inline presentation attributes (`stroke`, `fill`, etc.) from child elements so they inherit from the root at render time. Icons must be 24×24 viewBox, stroke-only, flat geometry (no `<g>`/`<defs>`/`<mask>` — the parser is intentionally simple and regex-based, not a real XML parser). It also strips layer `id`s and `data-*` attributes and keeps separate elements as authored: sources are **unmerged**, one element per part of the icon. It only rewrites files, except when cleaning would change the rendering (a group's `transform`, a `stroke-dasharray`): since that can't be detected afterwards, it leaves that icon as exported, reports each offending element (line, layer `id`, value, fix) and exits 1, so `pnpm icons` stops and `icons:check` keeps failing until it's fixed in the design tool.

   **`tools/build-icons/check-icons.ts`** (`pnpm icons:check`) is the read-only counterpart: it checks every source SVG is already normalized and flags export features to correct in the design tool — errors for `transform`, `<use>`, geometry crossing the 1px margin and dots too short for Safari, a warning for layers with different line caps/joins that can't merge into one path. It also validates each `<name>.json` against `icon.schema.json` (with `ajv`, a dev-only dependency) and flags a missing or orphaned `.json`. It checks each icon's animation file, if any, against its SVG (`animation` rule; see step 5) and flags one with no SVG. Rules live in `check-icons.lib.ts` as pure `checkIcon(svg, variant)` / `checkMetadata(json)` → `Issue[]` (animation rules in `animated.lib.ts`, `checkAnimations(svg, definition)`); rule ids and the `Issue` type are in the import-free `check-rules.ts`. The Lab (`apps/lab`) doesn't re-implement any rule: `gen-icon-nodes.ts` runs these checks and writes each icon's issues into the Lab's data, so add or change rules here, not in the Lab.

3. **`tools/build-icons/build.ts`** — the codegen. Invoked as `pnpm gen` from each package. `--target react` (default) or `--target vanilla` selects the output package (`packages/react/src` vs `packages/core/src`). For each SVG it: parses to an `IconNode` tuple tree (`[tag, attrs, children?]`), strips inherited attrs again, converts `<circle>`/`<rect>`/other basic shapes to path data and merges elements with the same line cap/join into one `<path>` (stroke variant only, `mergePathNodes`; sources stay unmerged for the future animated build), camelCases attrs (React target only), and writes one `<name>.ts` per icon plus an `index.ts` barrel with `export { default as PascalName }` lines (plus alias re-exports from each icon's JSON `aliases`). Non-default variants also get a `<variant>.ts` entry file (e.g. `rounded.ts`) that re-exports `./icons-<variant>`.

4. **tsdown** (`--config-loader tsx`) bundles the generated `src/` into `dist/` with the CJS/ESM/`.d.ts` matrix declared in each package's `exports`.

5. **`animations/<variant>/<name>.ts` + `tools/build-icons/build-animated.ts`** — the animated icons (`@jedd-icons/react-animated`). An animation file is motion only: plain data typed `IconAnimations` (from `@jedd-icons/shared`, re-exported by `animations/types.ts`), with animations **named for their motion** (`nudge`, `spin`; `"default"` and preset names are reserved), an optional `default` pointing at one of them or a preset, and optional `groups` of elements that move together. Targets are elements **by position in the cleaned SVG** (layer `id`s are stripped), so re-exporting an animated icon must keep its element order: `icons:compare` lists animated icons whose elements moved. `build-animated.ts` is separate from `build.ts` so the static packages' output can't change: it keeps the source elements unmerged, marks each with `data-part="<position>"`, wraps them in `<g data-group="icon">` (plus a `<g data-group>` per group), and bakes in the animation file. Variant-aware like `build.ts` (`src/icons-<variant>` + `src/<variant>.ts` for non-default variants). `animation-files.ts` loads animation files (dynamic `import`, so these scripts need tsx) for `icons:check`, `gen-icon-nodes` and the codegen.

Naming: `chevron-right.svg` (kebab) → `ChevronRight` component (Pascal). This transform lives in both `build.ts` and `createJeddIcon.tsx` — keep them consistent.

### React runtime (hand-written, not generated)

`packages/react/src/{Icon.tsx,createJeddIcon.tsx,JeddProvider.tsx,types.ts}` are the real source; `Icon` and `createJeddIcon` are internal (not exported from the package). `createJeddIcon(name, iconNode, variant)` wraps the shared `Icon` component, injecting `jedd jedd-<name>` classes. `Icon` applies consumer props (`size`, `color`, `strokeWidth`, `absoluteStrokeWidth`) and pulls variant defaults + `resolveStrokeWidth` from `@jedd-icons/shared`. `absoluteStrokeWidth` keeps stroke visually constant across sizes.

### Animated runtime (hand-written, not generated)

`packages/react-animated/src/{Icon.tsx,JeddProvider.tsx,player.ts,createAnimatedJeddIcon.tsx,AnimateIcon.tsx,useTrigger.ts,types.ts}`. The package is **standalone** — no runtime dependency on `@jedd-icons/react`; like it, it bundles `@jedd-icons/shared`, where the animation data format and the presets (`draw`, `draw-loop`, `pulse`, `wiggle`) live, framework-free. `Icon.tsx` is an internal copy of `packages/react/src/Icon.tsx` that differs only in which `JeddProvider` context it reads — **keep the two identical** so an icon at rest renders the same from either package. `createAnimatedJeddIcon(name, iconNode, animations, default?, variant?)` is internal (`@lintignore`, like `createJeddIcon`). Its `JeddProvider` is its own context (doesn't reach static icons, and the static one doesn't reach these): the four styling props, the animation options, `fallbackAnimation` and `reducedMotion`; an option resolves icon prop → `<AnimateIcon>` → provider → default. `player.ts` is framework-free and drives the rendered `<svg>` with Motion's vanilla `animate()` by `data-part`/`data-group` selectors. `"default"` is a pointer, not an animation: it plays the icon's declared `default`, else the provider's `fallbackAnimation`, else `draw`; an unknown name plays that too (warning once in development, unless the name came from an `<AnimateIcon>`).

## Packages

- `@jedd-icons/shared` (private) — types + variant defaults + `resolveStrokeWidth` + the animation data format and presets. Built first; `react`/`core`/`react-animated` depend on it.
- `@jedd-icons/react` / `@jedd-icons/core` — the two **published** packages (npm, public). Both expose only the `.` export.
- `@jedd-icons/react-animated` (private for now, not published) — animated icons on Motion (peer dependency), standalone (no dependency on `@jedd-icons/react`). The Lab previews it next to each icon.
- `@workspace/ui` (private) — shadcn/ui component library consumed by the docs app. Add components with `pnpm dlx shadcn@latest add <name> -c apps/www-docs`; they land in `packages/ui/src/components/` and import as `@workspace/ui/components/<name>`. There's no `./hooks/*` export yet (knip flags an export with no files): if a component brings a hook (e.g. `sidebar` → `use-mobile`), add `"./hooks/*": "./src/hooks/*.ts"` back to `packages/ui/package.json` `exports`.
- `apps/www-docs` — the gallery + docs site. TanStack Start + Vite + Fumadocs (MDX), deployed to Cloudflare via Wrangler. `predev`/`prebuild` run `gen-data` (`gen-releases` + `gen-contributors` + `gen-categories` + `gen-tags`) and fumadocs generation; the TanStack `routeTree.gen.ts` is generated and lint-ignored.
- `apps/lab` — internal Vite playground for inspecting source and generated icon geometry. Its `gen-data` script runs `gen-icon-nodes`, including the issues produced by the shared icon checks. It also plays each icon from `@jedd-icons/react-animated`, with triggers/options in the sidebar and the matching JSX.

## Releasing

Changesets-driven. A PR that changes a **published** package (`@jedd-icons/react`/`@jedd-icons/core`) needs `pnpm changeset` — the summary you write *is* the public changelog line. Docs-only and internal-package (`shared`, `ui`) changes don't need one. `react` and `core` are a `fixed` group in `.changeset/config.json`: they always share a version, so a changeset for either releases both (`gen-releases.ts` relies on this for "since" versions). Pre-1.0: breaking changes ride a **minor** bump. The `Release` GitHub Actions workflow automatically maintains the rolling "Version Packages" PR, but publishing is manual: dispatch the workflow with the `publish` input checked. Locally, the equivalent commands are `pnpm version` then `pnpm release`.
